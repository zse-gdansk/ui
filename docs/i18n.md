# Tłumaczenia

Każdy tekst, który biblioteka pokazuje sama z siebie (etykiety przycisków, `aria-label`, komunikaty błędów, liczniki), pochodzi z katalogu w `src/i18n/`. Na razie jest jeden katalog, polski, i jest domyślny: bez żadnej konfiguracji wszystko działa po polsku.

## Pliki

| Plik                   | Co zawiera                                                            |
| ---------------------- | --------------------------------------------------------------------- |
| `src/i18n/types.ts`    | `Messages`: kształt katalogu, pogrupowany po komponentach             |
| `src/i18n/pl.ts`       | polski katalog                                                        |
| `src/i18n/plural.ts`   | `plural(locale, n, forms)`: forma liczebnika przez `Intl.PluralRules` |
| `src/i18n/context.tsx` | `LocaleProvider` i `useMessages()`                                    |

`locale` w katalogu (`"pl-PL"`) to kod dla `Intl`: formaty dat, liczb i procentów, odmiana, wielkie litery (`toLocaleUpperCase`). Komponent nigdy nie wpisuje `"pl-PL"` na sztywno, bierze `t.locale`.

## W aplikacji

```tsx
import { LocaleProvider } from "@zse-gdansk/ui";

// Zmiana pojedynczych tekstów, reszta z domyślnego katalogu.
<LocaleProvider override={{ common: { close: "Zamknij okno" } }}>
    <App />
</LocaleProvider>;
```

`override` scala się płytko w obrębie grupy: podajesz tylko te klucze, które zmieniasz. Prop komponentu (`closeLabel`, `emptyText`…) dalej wygrywa z katalogiem, więc pojedyncze miejsce zmienia się bez providera.

## W komponencie

```tsx
import { useMessages } from "../../i18n/context";

export function Modal({ closeLabel, ...props }: ModalProps) {
    const t = useMessages();
    return <button aria-label={closeLabel ?? t.common.close} />;
}
```

- **Żadnego tekstu interfejsu w JSX ani w domyślnych propsach.** Prop tekstowy jest opcjonalny, bez wartości domyślnej, a w renderze `prop ?? t.grupa.klucz`.
- **Tekst zależny od liczby albo wartości to funkcja** w katalogu (`added: (n) => …`, `emptyFor: (query) => …`). Nie skleja się zdań z kawałków w komponencie, bo szyk w innym języku jest inny.
- **Liczebniki przez `plural`**, z formami `one`/`few`/`many`/`other` tego języka, w katalogu, nie w komponencie.
- **Formatery `Intl` z `t.locale`**, zapamiętane per język w `Map`, nie jako stała modułu z wpisanym językiem.
- **Funkcje poza Reactem** (formatowanie rozmiaru pliku, reguły hasła, skróty) przyjmują `locale` albo fragment katalogu parametrem, z domyślnym `pl`.
- **Wspólne teksty w `common`** (Zamknij, Anuluj, Wyczyść), reszta w grupie komponentu.

## Nowy tekst

1. Klucz w `Messages` w `types.ts`, w grupie komponentu (nowa grupa, jeśli komponent jej nie ma).
2. Wartość w `pl.ts`. TypeScript nie przepuści katalogu bez nowego klucza, więc przyszłe katalogi też go dostaną.
3. W komponencie `t.grupa.klucz`.

## Przełącznik języka

`LocaleSwitcher` nie zna żadnej biblioteki tłumaczeń: dostaje `value` i `onValueChange`. Jeśli `onValueChange` zwróci obietnicę (np. `i18n.changeLanguage`), w przycisku kręci się spinner, a nowy język jest zaznaczony, dopóki obietnica się nie skończy. Nazwy języków pochodzą z `Intl.DisplayNames`, więc nie ma ich w katalogu: każdy język ma nazwę własną („English”, „Українська”) i obok nazwę w aktualnym języku aplikacji, czyli z `value` („angielski” po polsku, „Англійська” po ukraińsku). W innym menu, np. w `UserMenu`, ten sam wybór daje `LocaleSubmenu` z tymi samymi propsami; spinner stoi wtedy obok etykiety „Język” i zostaje także po zamknięciu i ponownym otwarciu menu.

Z react-i18next:

```tsx
const { i18n } = useTranslation();
const language = i18n.resolvedLanguage ?? "pl";

useEffect(() => {
    document.documentElement.lang = language;
}, [language]);

<LocaleProvider messages={catalogs[language] ?? pl}>
    <LocaleSwitcher
        locales={["pl", "en"]}
        value={language}
        onValueChange={(next) => i18n.changeLanguage(next)}
    />
</LocaleProvider>;
```

Flagi przekazuje aplikacja, na przykład z [country-flag-icons](https://www.npmjs.com/package/country-flag-icons): `flags={{ pl: PL, en: GB, uk: UA }}` z importem `import { GB, PL, UA } from "country-flag-icons/react/3x2"`. Biblioteka nie zależy od tej paczki, a bundler dołącza tylko zaimportowane flagi. Kraj wybiera aplikacja, bo język to nie kraj. Z flagami zaznaczenie przechodzi z kropki na znacznik po prawej.

`resolvedLanguage`, nie `language`: to język faktycznie wybrany z `supportedLngs` („en” zamiast „en-US”). Atrybut `lang` na `<html>` ustawia aplikacja, biblioteka nie dotyka dokumentu. Przy routingu z językiem w adresie (next-intl) `onValueChange` zmienia ścieżkę, a `value` to język z adresu.

## Nowy język

Nowy plik obok `pl.ts` (np. `en.ts`) z obiektem typu `Messages`, eksport w `src/i18n/index.ts` i `src/index.ts`. Aplikacja przekazuje go przez `<LocaleProvider messages={en}>`. Na razie świadomie nie ma innych katalogów niż polski.

Poza katalogiem zostają rzeczy niezależne od języka: symbole klawiszy na Macu (⌘ ⇧), nazwy języków programowania w `CodeBlock`, ziarno generatora awatarów (normalizowane zawsze tak samo, żeby ten sam uczeń miał ten sam awatar niezależnie od języka).
